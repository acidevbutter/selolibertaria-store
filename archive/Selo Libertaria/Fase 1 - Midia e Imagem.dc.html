Fase 1

Imagem: subir, recortar, reusar

Primeira fase porque nada mais importa se publicar uma foto exige sair do admin. Hoje o campo de imagem aceita só URL colada — sem upload, sem recorte, sem descrição, sem reuso. Esta fase entrega arquivo → recorte → biblioteca, e libera a Fase 2 (o editor de blocos depende de poder inserir imagem no meio do texto).

"Usada em 3 lugares" é o que impede o erro clássico: apagar uma imagem e quebrar três páginas sem saber. Antes de excluir, o admin lista onde ela aparece.

A biblioteca é a mesma em editorial, evento e produto. Um único seletor de imagem no admin inteiro — hoje são dois componentes diferentes.

Backend O que precisa existir para a Fase 1 rodar

1 · Armazenamento de arquivo

Onde a foto vive

Hoje não há upload: o banco guarda uma string de URL externa. Precisa de um bucket (S3/R2/Supabase Storage) e URL assinada para envio direto do navegador — o arquivo não deve passar pelo servidor Next.

Rotas: POST /api/admin/media/sign (devolve URL de envio) · POST /api/admin/media (registra o arquivo enviado).

2 · Tabela nova

MediaAsset

Campos: id, storageKey, filename, mimeType, bytes, width, height, alt, uploadedById, createdAt. É o registro único que a biblioteca lista.

Migração + índice em createdAt e busca por filename/alt.

3 · Recorte como dado

MediaCrop

O recorte não pode ser destrutivo. Guardar por uso: assetId, aspect ("16:9"), x, y, w, h, rotate, flip, grayscale. A mesma foto tem recortes diferentes em lugares diferentes.

Os campos de conteúdo passam a apontar assetId + cropId, não uma URL solta.

4 · Derivadas

Compressão e tamanhos

Gerar WebP com fallback JPG em 3 larguras (400 / 900 / 1600) aplicando o recorte. Sob demanda com cache no CDN é suficiente — não precisa de fila.

Se usar next/image com remotePatterns, o domínio do bucket precisa ser liberado na config.

5 · Uso reverso

"Usada em 3 lugares"

Tabela de vínculo MediaUsage (assetId, entityType, entityId, field) escrita junto do salvamento do conteúdo. É o que permite bloquear exclusão com aviso em vez de quebrar páginas.

Rota: DELETE /api/admin/media/[id] devolve 409 com a lista de usos.

6 · Compatibilidade

As URLs que já existem

O conteúdo atual aponta para links externos. O leitor precisa aceitar as duas formas durante a transição, e vale um script que baixa as imagens externas e cria MediaAsset para cada uma — senão a biblioteca nasce vazia e as páginas antigas seguem dependendo de link de terceiro.

Permissão: reaproveitar editorial.write e catalog.write; não criar capability nova.

Aceite A fase está pronta quando

— A dona do site publica a capa de um evento sem abrir nenhum outro programa, arrastando o arquivo.

— A mesma foto aparece recortada em 16:9 no hero e em 3:4 no card, sem subir duas vezes.

— Não existe mais campo que exija colar URL para uso normal (colar link continua possível, como atalho).

— Tentar excluir uma imagem em uso mostra onde ela está e não deixa quebrar a página.

— Toda imagem nova tem descrição preenchida: o botão de confirmar depende dela.
